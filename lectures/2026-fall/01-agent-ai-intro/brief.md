## 1. 청중, 목표, 말투

### 1.1 청중

조선대학교 동아리 학생. ChatGPT나 Gemini를 써봤을 수 있지만, 회사명·모델명·앱 이름부터 혼동할 수 있다. API, 토큰, 저장소, 터미널, 에이전트 등의 개발 용어를 알고 있다고 가정하지 않는다.

발표자는 로봇·회로·AI 프로젝트 경험을 바탕으로 직접 사용한 방법과 선택 기준을 공유한다. 모든 소프트웨어·보안 지식을 이미 알고 있거나, AI가 모든 결정을 대신한 것처럼 묘사하지 않는다.

### 1.2 한 문장 목표

**내 공부와 프로젝트에 맞는 AI를 고르고, 필요한 범위만 맡기고, 결과를 확인한 뒤 내 작업 이력으로 남기는 방법을 이해한다.**

수업이 끝나면 학생은 다음을 자신의 말로 설명할 수 있어야 한다.

1. OpenAI·GPT·ChatGPT·Plus가 서로 다른 종류의 이름인 이유.
2. 개인 구독·학생 혜택·학교 크레딧·API 사용이 어떻게 다른지.
3. LLM을 사용하는 대화 서비스와 도구를 실행하는 Agent 시스템의 관계.
4. CoT·오케스트레이션·하네스·Skill·MCP가 각각 맡는 역할.
5. 컴퓨터에서 실행하는 작업을 휴대전화로 확인·승인할 때 필요한 조건.
6. 프롬프트와 검증 기준, GitHub 기록이 왜 함께 필요한지.

### 1.3 톤과 언어

쉽고 가볍게 설명하되 학생을 무시하거나 서비스 사용자를 조롱하지 않는다. “AI를 쓰는 사람은 다 아는 용어” 같은 표현을 피한다. 상황형 비유는 허용하지만 그것을 기술적 정의로 대체하지 않는다.

슬라이드와 발표 원고는 모두 한국어로 쓴다. 제목·핵심 문장·본문·표·도식·주석·목차를 실제로 한국어로 다시 작성한다. 초보자에게 중요한 용어는 첫 등장에 한국어 의미와 원어를 병기한다. 예: `하네스(Harness) · 에이전트 실행 환경`, `크레딧(Credit) · 사용 예산 단위`. 제품명·코드·경로·URL·실제 화면의 원문은 보존하고 필요한 한국어 설명을 덧붙인다.

표지에 적을 한국어 부제: **“어떤 AI를 고르고, 어떻게 일을 맡기고, 무엇을 내 기록으로 남길까?”**

## 5. 회사·모델·앱 설명: 이름부터 확실히 구분한다

### 5.1 핵심 비교표

| 범주 | 학생에게 풀어 말할 뜻 | OpenAI 쪽 예 | Anthropic 쪽 예 | Google 쪽 예 |
|---|---|---|---|---|
| 회사/개발 주체 | 누가 만드는가 | OpenAI | Anthropic | Google / Google DeepMind |
| 모델 또는 모델군 | 요청을 받아 처리하는 AI | GPT 계열 | Claude 계열 | Gemini 계열 |
| 앱/서비스 | 사용자가 접속해서 쓰는 제품 | ChatGPT | Claude 앱 | Gemini 앱 |
| 개인 요금제 | 어떤 이용 조건을 구독하는가 | ChatGPT Plus | Claude Pro | Google AI Plus / Pro |
| Agent 작업 제품 | 파일·도구를 다루며 일하는 환경 | Codex | Claude Code | Antigravity |

이 표는 교육용 범주 구분이다. 제품 하나가 여러 역할을 겸하거나 같은 이름이 모델과 앱에 쓰일 수 있다. 특히 Claude와 Gemini는 이름만으로 모델/앱을 구분하기 어려우므로 문장에 범주를 붙인다. Codex라는 이름의 역사까지 늘어놓지 말고 이번 수업에서는 현재 코딩 Agent 제품의 의미로 사용한다. [S01][S02][S05][S06][S08][S09][S28]

화면에서 강조할 오해:

- “OpenAI 유료 모델이 Plus”가 아니라, **회사는 OpenAI, 구독은 ChatGPT Plus, 사용 모델은 별도로 정해진다.**
- `Google AI Pro`라는 요금제와 이름에 `Pro`가 들어간 Gemini 모델은 같은 분류가 아니다.
- 회사의 대표 모델이 API 문서에 있다고 해서 학교 플랫폼이나 모든 개인 요금제에서 선택 가능한 것은 아니다.

### 5.2 세 회사를 같은 축으로 소개한다

각 회사에 대해 '대표 모델 이름 → 사용하는 제품 → 이번 강의와 연결되는 사용 흐름 → 제한 한 가지'를 같은 순서로 설명한다. 회사 연혁·창업자·투자 소식은 본편에서 제외한다.

**OpenAI:** GPT 계열이 실제 답변·작업 판단에 쓰이는 모델임을 설명한다. 공부를 위한 ChatGPT 대화와 Codex를 통한 프로젝트 작업을 연결하되, 앱의 모드·모델·사용량을 구분한다. 문서 조사, 파일 작업, 코딩 등을 이야기할 때에는 해당 제품과 계정에서 실제 제공되는 기능만 보여준다. [S01][S02][S03][S22]

**Anthropic:** Claude 모델군과 Claude 앱, Claude Pro, Claude Code를 나눈다. 전공 질문을 차근차근 검토하는 사용 사례와 파일·프로젝트를 다루는 Agent 사용 사례를 모두 제시한다. 'Claude는 공부용이고 프로젝트는 못 한다'는 오해를 만들지 않는다. 공부용 추천은 아래의 발표자 의견으로 분리한다. [S05][S06][S07]

**Google:** Gemini 모델과 Gemini 앱, Google AI 요금제를 분리한다. 학습 자료를 바탕으로 질문·정리하는 사용 흐름과 학생 혜택을 연결한다. Google 서비스와의 연결, 개발 작업 기능은 계정과 요금제 조건이 다를 수 있음을 알려준다. 학생 혜택을 Google의 모든 유료 기능·API를 무제한 제공하는 것으로 설명하지 않는다. [S08][S09][S10]

## 6. 요금제: 사실 표와 발표자의 추천 표를 나눈다

### 6.1 먼저 설명할 네 가지

**개인 구독:** 정해진 제품의 기능·이용량을 사용하는 계약.
**API:** 다른 프로그램이 모델을 호출하는 인터페이스이며, 개인 구독과 별도 과금·권한일 수 있다.
**학교 크레딧:** 학교 서비스에서 사용을 집계하는 예산 단위.
**토큰:** 모델이 입력·출력을 처리할 때 사용하는 텍스트 등의 단위. 한국어 한 글자나 한 단어와 항상 같다고 설명하지 않는다.

정액 구독을 했다고 API가 모두 무료가 되지 않는다. 반대로 학교 API 사용 권한이 생겼다고 ChatGPT Plus나 Claude Pro 계정이 발급되는 것도 아니다. 인증 방식을 확인하는 것이 비용·기능 확인의 출발점이다. [S03][S07][S13][S14][S15]

### 6.3 Gemini 학생 혜택 — 이전 연도 안내를 그대로 쓰지 않는다

사용자가 제공한 한국 구독 페이지 화면에는 **Google AI Plus 1년 무료 학생 혜택**과 “프로모션이 곧 만료”된다는 안내가 표시되어 있었다. 해당 화면만으로 구체적 신청 기한, 개인별 자격, 자격 재확인, 결제 수단, 자동 갱신과 무료 기간 종료 후 가격은 확정할 수 없다. 실제 신청 화면에서 조건과 금액을 확인하도록 한다. 같은 화면의 일반 AI Plus 가격은 월 ₩7,500으로 표시됐으나, 학생 혜택 종료 후의 적용 금액과 시점은 계정별 신청 화면·약관에서 재확인한다. [S09][S10][S11][U02]



“학교 이메일로 학생 신분을 증명한다”와 “학교가 관리하는 Google 계정으로 해당 혜택에 가입한다”는 다를 수 있음을 짚는다. 가입 실습은 하지 않는다.

세 서비스를 동시에 결제하라는 결론으로 만들지 않는다. 회로 문제 예시는 '주어진 조건·단위·부호·가정과 계산을 교재/강의자료로 확인한다'는 학습 원칙으로 연결한다. 검증하지 않은 회로별 성능 비교는 넣지 않는다.

### 6.5 ChatGPT와 Codex의 사용량 관계

발표자의 일반 Chat와 Codex를 나누어 쓰는 장점은 유지하되, **ChatGPT 화면의 모든 작업이 Codex와 완전히 별도인 것처럼 설명하지 않는다.**

공식 문서는 적용되는 플랜에서 Work·Codex 등의 작업이 사용량/크레딧을 공유한다고 안내한다. 일반 Chat 및 일부 별도 기능의 한도와는 구분된다. 따라서 설명할 때 '일반 Chat', 'ChatGPT Work', 'Codex'를 명시하고 실제 계정의 사용량 화면을 기준으로 삼는다. Claude Pro/Max의 Claude와 Claude Code 사용량은 공유된다는 점도 같은 비교 축으로 알려준다. [S04][S07]

API 키로 인증한 작업은 구독 로그인과 청구 경로가 달라질 수 있다. '구독 중이니 이 터미널 작업도 포함된다'고 추측하지 않는다. 정확한 시간창·횟수·주간 한도는 계정 화면에서 재확인하고 고정 메시지 수를 보장하지 않는다.

### 6.6 Codex 리셋 추적 사이트

사용자 지정 링크: https://codex-resets.com

**역할:** 공개된 리셋 관련 발표를 모아보는 비공식 참고 사이트. 개인 계정의 남은 사용량을 확인하거나 직접 리셋을 실행하는 공식 관리 화면이 아니다. 공식 사용량 대시보드와 발표 원문을 우선한다. 향후 추가 리셋은 보장되지 않는다. 비밀번호·API 키를 입력하도록 안내하지 않는다. [S16][S04]

화면에서는 링크 카드와 '비공식 / 내 잔여량 아님 / 미래 리셋 보장 없음' 세 가지를 짧게 붙인다. 수업 직전 확인하지 않은 최근 리셋 횟수·날짜는 본편에 고정하지 않는다.

## 7. CSU AI: 학생에게 먼저 알려줄 현실적인 선택지

### 7.1 서비스 정체성과 접속

CSU AI는 이번 수업에서 사용하는 학교 서비스 명칭이다. 제공 문서에는 베이즈/BAZE와 Gateway라는 명칭도 나타날 수 있다. **학교가 새로운 GPT 모델을 자체 개발했다는 뜻이 아니라, 여러 모델을 이용할 수 있도록 제공하는 서비스·접속 경로**로 설명한다. 공식 문서에서 다중 모델 제공과 Gateway 연동을 확인할 수 있다. [S12][S13][S14][S15]

발표자가 안내한 접속 경로: **조선대학교 종합정보시스템 → CSU AI 진입**. 실제 메뉴 이름과 화면은 발표 전 계정에서 확인한다. 학교 비밀번호, 학번, 이메일, 토큰이 보이는 화면은 자료에 넣지 않는다. [U01]

| 여러 공급자의 모델을 사용할 수 있음 | 공식 문서 확인 | 학교 계정에서 실제 선택 가능한 목록과 구분 [S12][S13] |
| 모델·입출력에 따라 크레딧 사용량이 달라짐 | 공식 문서 확인 | 메시지 횟수만으로 소비량을 비교하지 않음 [S13] |
| 조대생은 현재 무료로 이용 가능 | **발표자가 제공한 학교 운영 정보** | “발표자 안내 기준 현재 학생 이용료 없음; 학교 정책·자격 확인” [U01] |
| 학생이 추가 크레딧 발급을 신청할 수 있음 | **발표자가 제공한 학교 운영 정보** | 가능성은 소개하되 신청 링크·담당자·자동 승인 여부를 만들지 않음 [U01] |
| 다른 구독보다 토큰이 상대적으로 적게 느껴짐 | **발표자의 사용 경험** | '사용 가능한 크레딧/사용량이 제한적으로 느껴졌다'로 설명 [U01] |
| Codex CLI·Claude Code Gateway 연동 | 공식 가이드 확인 | 지원 클라이언트·인증·허용 모델·크레딧 조건을 표시 [S14][S15] |

'무료'를 무제한, 영구 무료, 모든 재학생에게 동일량 보장으로 바꾸지 않는다. 개인이 납부하지 않아도 학교 예산·조직 한도가 존재할 수 있다.

추가 신청의 정확한 메뉴·대상·지급량·심사·처리 기간은 이 문서 작성 과정에서 독립 확인하지 못했다. 자료 제작을 막지는 않되, 본편에는 간단한 조건 문구를 넣고 상세 절차는 확인 전까지 부록에도 확정 정보로 넣지 않는다.

### 7.3 토큰·크레딧·컨텍스트 창을 섞지 않는다

토큰은 처리량 단위, 크레딧은 사용 예산, 컨텍스트 창은 한 번에 다룰 수 있는 문맥의 범위라는 식으로 구분한다. '학교 서비스의 토큰이 적다'는 경험을 '같은 모델의 지능이나 컨텍스트 창이 반드시 작다'는 주장으로 바꾸지 않는다.

공식 크레딧 안내는 입력·출력 단가를 나누고, 이전 대화와 문서가 입력에 포함될 수 있다고 설명한다. 따라서 모델 선택·긴 대화·큰 문서가 사용량에 영향을 준다는 수준으로 설명한다. 학교 월 지급량이나 모든 구독 대비 소진 속도는 추정하지 않는다. [S13]

### 7.4 API로 Agent 환경에 연결하기

설명용 구조:

```text
내 컴퓨터의 Codex CLI / Claude Code
                ↓ 허용된 API 키와 설정
       조선대학교 Mindlogic Gateway
                ↓ 계정에 허용된 모델
          모델 응답 / 도구 호출
                ↓
내 컴퓨터의 허용된 파일 작업·명령 실행
                ↓
      학교 계정의 크레딧으로 집계
```

도식에는 '설명용 단순화'를 표시한다. API 요청이 로컬 명령을 직접 실행하는 것처럼 그리지 않는다. 모델의 도구 호출을 실제로 실행하는 주체는 권한을 가진 클라이언트/실행 환경이다.

공식 가이드는 Codex CLI의 커스텀 제공자 연결과 Claude Code의 Gateway 연결을 안내한다. 이것만으로 모든 데스크톱 앱 메뉴, 클라우드 기능, 원격 기능까지 동일하게 제공된다고 결론 내리지 않는다. [S14][S15]

본편은 이 구조와 '개인 구독과 별도 경로'까지 설명한다. 설치 명령, 환경 변수, 인증 예외는 후속 자율 참고자료에 둔다. 실제 API 키는 예시·스크린샷·README·Git 이력에 넣지 않는다. 키 발급이나 유료 사용을 강제로 실행하지 않는다.

특히 Claude Code Remote Control은 현재 구독 로그인과 지원 환경이 필요하며 API 키·외부 Gateway 경로는 지원되지 않는다고 공식 문서에 명시되어 있다. 학교 API 활용과 원격 기능을 하나의 무료 패키지처럼 소개하지 않는다. [S25]

### 8.2 영상 앞뒤에서 할 말

영상 앞의 관찰 질문은 세 가지다. 이것은 영상 내용에 대한 요약이 아니라, 학생에게 주는 관찰 틀이다.

> “지금부터 영상을 보고 용어를 전부 외울 필요는 없습니다. 무엇이 판단하고, 무엇이 실제로 행동하고, 도구와 작업 방법은 어디에서 오는지만 봐주세요. 세 편을 본 다음 같은 내용을 우리 프로젝트 사례로 다시 정리하겠습니다.”

영상 뒤의 연결 문장:

> “방금 본 표현들을 이제 역할별로 나눠보겠습니다. 답을 만들어내는 모델, 실제 일을 진행하는 실행 환경, 연결하는 도구, 반복 작업 지침은 서로 다른 부분입니다.”

개별 영상의 구체적 장면을 인용하려면 해당 장면과 시점을 확인하고 원고에 연결한다. 확인하지 못한 장면·발언을 원고에 만들어 넣지 않는다. 영상의 과거 제품 정보가 현재 기능과 다르면 제작 시 공식 문서로 구분해서 설명한다.

### 8.3 HTML 및 발표 환경

기본은 세 링크를 순서대로 여는 영상 카드다. 기존 엔진이 지원하면 클릭 후 플레이어를 여는 방식도 허용한다. 자동 재생을 강제하지 않는다. 임베드가 막히면 원본 YouTube 링크를 여는 대안을 제공한다. 발표 환경의 네트워크·소리·권한·광고/로그인 화면을 사전 확인할 항목으로 남긴다.

PDF와 visual PPTX에서는 재생을 보장하지 않는다. 번호·원본 링크·관찰 질문을 담은 정적 카드로 대체한다. 원고에는 어느 영상을 언제 시작하고 돌아오는지 표시한다. 영상 파일을 무단 다운로드하거나 공개 저장소에 재업로드하지 않는다.

## 9. 영상을 본 뒤 개념을 하나의 사례로 다시 설명한다

공통 사례는 **“이번 동아리 강의의 brief.md를 읽고 HTML 슬라이드를 만들어 검수하고 GitHub에 기록하기”**다. 이 저장소가 실제 완성·배포되었다는 증거가 없으면 '완료 사례'가 아니라 '지금 구축하는 작업 흐름/설명용 예시'라고 표시한다.

### 9.1 LLM과 Agent

LLM은 입력 문맥을 받아 언어 등으로 응답하는 모델이다. Agent는 목표에 따라 모델과 도구·상태·실행 환경을 사용해 작업을 진행하는 시스템으로 설명한다. 두 개를 같은 수준의 경쟁 제품처럼 비교하지 않는다. 현대의 많은 Agent는 LLM을 구성 요소로 사용한다. [S17]

| 단순 대화 예시 | Agent 작업 예시 |
|---|---|
| “HTML 슬라이드를 만드는 방법을 설명해줘.” | “허용된 프로젝트 폴더에서 파일을 만들고, 브라우저로 열어 확인하고, 검사 결과를 남겨줘.” |
| 설명과 코드 예시를 답으로 받음 | 파일 생성·실행·검사 등 실제 도구 사용이 뒤따를 수 있음 |

웹의 채팅 UI에도 Agent 기능이 있을 수 있다. 따라서 '웹=LLM, 앱=Agent'로 나누지 않는다. 판단 기준은 화면 모양이 아니라 실제 수행 권한과 작업 방식이다.

### 9.2 CoT — 단계적 추론과 실제 행동을 구분

CoT(Chain of Thought)는 문제를 중간 단계로 나누어 풀도록 유도하는 추론·프롬프팅 접근을 소개하는 용어다. 역사적 연구의 기법과 현재 추론 모델의 구현을 완전히 같은 것으로 취급하지 않는다. [S18]

학습용 예시:

```text
그냥 결론: “이 요금제를 쓰세요.”
설명 가능한 풀이: 목적 확인 → 제공 기능 확인 → 비용·한도 확인 → 조건부 선택
Agent 행동: 공식 페이지를 열기 → 정보 정리 파일 생성 → 링크 검사 → 결과 보고
```

위 예시는 설명을 위한 순서이며 모델의 숨겨진 내부 사고 로그가 아니다. CoT가 있다고 파일 접근이나 도구 실행 권한이 저절로 생기지 않는다. 긴 답변도 정확성을 보장하지 않는다.

이미 추론하는 모델에 '차근차근 생각해'를 붙이면 언제나 성능이 개선된다는 규칙으로 가르치지 않는다. 필요한 것은 검토 가능한 가정·수식 풀이·근거·검증 결과를 요청하는 것이다. [S19]

### 9.3 실행 루프와 중단 조건

설명용 루프: **목표 이해 → 필요한 행동 결정 → 허용된 도구 실행 → 결과 관찰 → 수정 또는 종료**. 실패 시 다시 시도할 수 있으나 무한 반복·무제한 비용을 허용하는 것이 목표는 아니다. [S17]

수업 예시: HTML 작성 → 브라우저 캡처 → 제목 잘림 발견 → 레이아웃 수정 → 다시 검사. “화면을 열지 못했다면 검수 완료라고 쓰지 않기”를 강조한다.

파일 삭제, 외부 전송, 유료 실행, 저장소 공개는 별도 승인 경계를 갖는다. 특히 강의 제작 Agent가 학교 계정 비밀번호나 개인 파일 전체를 읽을 이유는 없다.

### 9.4 오케스트레이션

이번 수업에서는 **작업을 어떤 순서와 역할로 나누고, 무엇을 근거로 다음 단계·재시도·중단을 결정할지 조직하는 것**으로 설명한다. 단일 Agent의 작업 흐름에도 적용할 수 있고, 여러 Agent를 병렬 사용해야만 성립하는 말이 아니다. [S17]

강의 제작 사례: 자료 조사 → 구성 → 집필 → 렌더링 → 검수 → 사람이 승인. 여러 Agent가 있다면 자료 조사·디자인·검수를 나눌 수 있지만 비용과 통합 검토가 추가된다. “Agent 수가 많으면 무조건 더 좋다”는 표현을 쓰지 않는다.

고정 순서로 진행하는 workflow와 상황에 따라 다음 행동을 선택하는 Agent를 구분하되, 실제 제품은 두 방식을 섞을 수 있다고 설명한다.

### 9.5 하네스

이번 수업의 작업상 정의: **모델 주위에서 문맥, 도구 실행, 권한, 작업 상태, 반복 루프와 결과 확인을 지원하는 실행 환경**. 단순히 채팅창의 모양이나 테마라는 뜻으로 축소하지 않는다.

Codex·Claude Code·Antigravity는 이 역할을 이해할 제품 예시다. 제품별 구현과 지원 범위는 서로 다르며, 모든 내부 구조가 같은 것은 아니다. 모델이 같아도 사용할 수 있는 도구·권한·파일 문맥·검증 방식이 달라 결과와 사용 경험이 달라질 수 있다는 관계를 설명한다. [S22][S25][S28]

비유: 모델이 문제를 푸는 엔진이라면 하네스는 작업 공간과 도구 사용을 관리하는 장치다. 비유에 대한 그림은 공식 아키텍처가 아니라 교육용이라고 표시한다.

### 9.6 Skill

Skill은 반복 가능한 작업 방법을 지침·자료·필요한 도구 자산으로 묶어 재사용하는 패키지다. Agent Skills 형식에서는 핵심 `SKILL.md`와 선택적인 스크립트·참고자료 등을 사용할 수 있다. 모델 가중치를 다시 학습시키는 것과 다르다. [S20]

이번 강의의 예: “항상 Pretendard를 쓰고, 정해진 여백을 지키고, Chart.js 그래프의 출처를 기록하고, 실제 캡처를 검사하는 발표자료 제작 방법”을 재사용 패키지로 구성할 수 있다.

구분할 파일:

| 파일 | 이 프로젝트에서의 역할 |
|---|---|
| `AGENTS.md` | 저장소 작업 지침과 읽을 문서를 안내 |
| `PRESENTATION_AGENT.md` | 공통 디자인·집필·출력·검수 규칙 |
| `brief.md` | 해당 주차에 무엇을 가르칠지 정한 입력 |
| `SKILL.md` | 지원되는 Skill 패키지의 진입 지침 |

현재 프로젝트에 규칙 Markdown이 있다는 이유만으로 이미 설치·인식되는 Skill이 되었다고 말하지 않는다. 실제 지원 형식과 로딩 경로에 맞춰 패키지화해야 한다.

### 9.7 MCP

MCP(Model Context Protocol)는 AI 애플리케이션이 외부 도구·데이터와 연결할 때 사용하는 공개 프로토콜로 소개한다. 모델 자체도 아니고, 연결만 하면 안전과 정확성이 보장되는 기능도 아니다. [S21]

설명용 예:

```text
Agent 애플리케이션의 MCP 클라이언트
                 ↕
             MCP 서버
                 ↕
      허용된 문서 / 저장소 / 외부 도구
```

MCP 서버가 반드시 원격 웹 서버인 것은 아니다. 로컬 또는 원격 구성이 있을 수 있다. GitHub나 파일을 이용하는 모든 도구가 반드시 MCP를 사용하는 것도 아니다. 기본 도구·직접 API·다른 커넥터도 존재한다.

**Skill = 어떻게 작업할지 정리한 방법**, **MCP = 도구·데이터를 연결하는 방식**으로 대비한다. Skill에 도구 사용법을 담거나 둘을 함께 사용하는 경우가 있어도 같은 것은 아니다. 연결 후에도 인증·허용 범위·행동 승인은 별도다.

### 9.8 한 화면에 회수할 역할 표

| 요소 | 강의 제작 사례에서 맡는 역할 |
|---|---|
| 모델/LLM | 자료를 이해하고 문장·코드·다음 행동을 생성 |
| CoT/단계적 설명 | 문제를 어떻게 나누어 검토할지 설명하는 접근 |
| Agent | 목표를 향해 도구 사용과 결과 확인을 반복하는 시스템 |
| 하네스 | 모델과 도구가 작업할 실행 환경 |
| 오케스트레이션 | 조사·제작·검수·승인의 순서와 역할 배치 |
| Skill | 반복 제작에 쓸 작업 방법과 참고자료 패키지 |
| MCP | 필요한 외부 도구·문맥에 연결하는 표준적 경로 중 하나 |
| 사람 | 목적·제약·승인·결과 수용 여부 결정 |

이 표를 모두 읽는 장면으로 만들지 않는다. 앞서 본 같은 사례 위에 요소를 표시하면서 핵심 차이만 회수한다.

## 10. 앱과 원격 기능: 실제로 어디에서 작업하는가

### 10.1 ChatGPT 앱과 Claude 앱

웹, 데스크톱, 모바일을 '더 똑똑한 모델 순위'로 나누지 않는다. 같은 서비스를 어디에서 어떤 권한으로 쓰는지의 차이다. 현재 공식 다운로드·제품 문서와 실제 화면을 기준으로 앱 이름과 메뉴를 쓴다. 데스크톱에서 채팅과 작업 모드가 통합되는 변화가 있으므로 과거 UI를 현재 기본 화면처럼 고정하지 않는다. [S22][S24][S29]

발표자 경험으로 사용할 문장:

> “제 환경에서는 웹보다 앱이 덜 버벅이고, 프로젝트 파일을 같이 다루기가 편했습니다. 그래서 오래 작업할 때는 앱을 선호합니다.” [U01]

이를 “앱이 언제나 더 빠르다”, “앱만 설치하면 답변 정확도가 올라간다”로 바꾸지 않는다. 로컬 파일을 읽고 수정하는 기능은 해당 모드·클라이언트·파일 권한에 달려 있다. 웹에서도 업로드·연결된 자료를 사용할 수 있으므로 접근 가능성을 이분법으로 만들지 않는다.

화면에는 실제 권한이 확인된 동작만 표시한다. 다운로드 화면을 보여줬다는 이유로 로컬 파일 수정까지 검증했다고 하지 않는다.

### 10.2 휴대전화로 컴퓨터에서 돌아가는 Agent 제어

핵심 메시지: **휴대전화가 프로젝트 실행 컴퓨터를 대체하는 것이 아니라, 연결된 컴퓨터의 작업을 지시·확인·승인하는 창이 될 수 있다.**

| 대상 | 공식 문서에서 확인한 흐름 | 반드시 붙일 조건 |
|---|---|---|
| ChatGPT/Codex Remote | 데스크톱에서 컴퓨터 연결을 설정하고 같은 계정·워크스페이스의 모바일 앱에서 작업 시작·확인·승인 | 지원 앱/OS/계정, 기기 승인, 컴퓨터 켜짐·온라인 [S23] |
| Claude Code Remote Control | 로컬 CLI/VS Code 세션을 웹·모바일에서 이어서 조작 | 해당 구독 로그인, 로컬 세션, 지원 엔드포인트·권한 [S25] |
| CSU AI Gateway 연결 | 학교 API로 지원 클라이언트의 모델 호출 | 이것만으로 위 원격 서비스 이용 자격을 얻지 않음 [S14][S15][S25] |

Claude Code Remote Control은 현재 Pro·Max·Team·Enterprise 등 지원 구독과 claude.ai 인증이 필요하고, API 키와 외부 Gateway 엔드포인트는 지원하지 않는다고 명시되어 있다. 기관 플랜은 관리자 설정도 영향을 준다. 이 제한을 숨기지 않는다. [S25]

“내 컴퓨터에서 실행”은 파일 작업·명령이 로컬이라는 뜻이며, 모델 추론까지 반드시 내 컴퓨터에서 이루어진다는 뜻은 아니다. 클라우드 실행 작업은 컴퓨터 전원과의 관계가 다를 수 있으므로 별도 모드로 구분한다.

도식은 **휴대전화 ↔ 서비스의 연결 기능 ↔ 켜진 내 컴퓨터 ↔ 허용된 프로젝트 파일**로 간단히 그린다. 실제 화면 전체 원격 조종, 컴퓨터 사용 기능, Agent 세션 제어를 같은 기능명으로 섞지 않는다. 승인하지 않은 기기나 타인의 컴퓨터 연결을 예시로 들지 않는다.

## 11. 프롬프트 작성법 — 설치 실습이 아닌 전후 비교

좋은 요청은 구현 언어를 많이 나열하는 것이 아니라 **목표, 현재 상태, 입력, 제약, 원하는 결과물, 검증 기준**을 전달한다. 모르는 기술은 선택지를 먼저 요청하고 직접 고를 수 있다.

나쁜 예:

> “AI Agent 동아리 PPT 멋있게 만들어줘.”

개선 예 — 화면에는 굵은 핵심만, 전체는 원고/읽기자료로:

```text
AGENTS.md와 공통 발표자료 규칙을 먼저 읽어줘.
이번 수업은 lectures/2026-fall/01-agent-ai-intro/brief.md를 기준으로 제작해줘.

목표: 회사·모델·앱을 혼동하는 대학생도 AI 선택과 Agent의 구조를 이해하게 한다.
제약: 60분 강의식이며 실습은 없다. 지정 영상 세 편을 개념 설명 전에 배치한다.
공통 디자인과 이미 확정된 이전 강의는 바꾸지 않는다.

요금제·학교 혜택·원격 기능은 공식 정보와 발표자의 추천을 구분한다.
확인하지 못한 값은 만들지 말고, 제작 가능한 부분부터 진행한다.

결과물: HTML, PDF, visual PPTX, 한국어 발표 원고, 출처와 QA 기록.
검증: 실제 렌더링, 글자 잘림, 출처, 슬라이드/대본 매칭, 영상 포함 시간 계산.
실행하지 못한 검사는 통과로 쓰지 않는다.

저장소 공개, 배포, 외부 전송, 유료 사용은 별도 승인 전 실행하지 않는다.
작업 결과와 남은 확인 사항을 구분해서 보고해줘.
```

발표자가 말할 경험: 도메인 지식이 있는 회로·로봇·AI의 목적과 조건은 직접 정하고, 잘 모르는 소프트웨어 구현은 선택지와 장단점을 추천받아 결정했다는 방식. 특정 기술을 모르는 상태에서 아는 척 강제하는 것이 좋은 프롬프트라고 설명하지 않는다. [U01]

## 12. GitHub로 프로젝트와 포트폴리오를 함께 관리한다

### 12.1 첫 시간에 필요한 범위

Git은 변경 이력을 다루는 도구이고, GitHub는 저장소를 호스팅하고 협업·검토를 돕는 서비스라는 정도에서 시작한다. 명령어 암기는 하지 않는다. 저장소, 커밋, 브랜치, PR은 아래 흐름 안에서 짧게 설명한다. [S26]

```text
내 작업 폴더 / 저장소
  → 변경 내용 확인(diff)
  → 의미 있는 변경 단위 기록(commit)
  → 필요하면 작업 가지(branch)에서 변경
  → 검토 요청(PR)
  → 검토 후 합치기(merge)
  → 승인된 결과 공개·소개
```

PR과 브랜치를 쓰지 않는 소규모 개인 작업도 가능하므로 이 절차를 GitHub 사용의 유일한 방식이라고 말하지 않는다. 다만 Agent가 만든 많은 변경을 검토하기에 유용한 예로 제시한다.

### 12.2 포트폴리오에 남길 것

강의용 예시는 바로 이 학기 자료 저장소다. 회차별 `brief.md`, 발표자료, 출처, 수정 이유, 검수 결과를 누적한다. 구현이 확인되지 않았다면 실제 완성된 저장소 화면 대신 구조 예시를 보여준다.

README/프로젝트 설명은 다음 내용을 담는다.

- 해결하려던 문제와 대상, 실제 실행 방법.
- 내가 결정한 목표·제약·선택과 AI에 맡긴 역할.
- 구조와 결과물, 실제로 실행한 테스트·관찰 결과.
- 알려진 한계와 다음 수정, 자료·코드의 출처와 이용 조건.

핀 고정 등 프로필 기능은 프로젝트를 소개하는 방법 중 하나로만 짧게 소개한다. 커밋 수나 잔디가 많다는 이유로 실력·기여를 입증한다고 설명하지 않는다. [S27]

핵심 원고:

> “AI가 코드를 만들었다는 사실만 남기면 내가 무엇을 했는지 보이기 어렵습니다. 어떤 문제를 정했고, 왜 그 방법을 골랐고, 어떻게 검증했는지를 같이 남겨야 내 프로젝트 설명이 됩니다.”

### 12.3 공개 전 주의

API 키, 학교 계정 정보, 개인정보, 사적 대화, 비공개 연구자료, 재배포 권한이 없는 강의 PDF·영상 원본을 넣지 않는다. `.env`를 제외해도 이미 커밋한 비밀값이 이력에서 자동으로 없어지는 것은 아니다.

사이트에서 대본을 숨겨도 저장소가 public이면 추적 파일·브랜치·이력에서 보일 수 있다. 기존 공개 승인 정책을 유지한다. 학생의 개인정보와 투표 원본은 이 저장소의 교육 콘텐츠가 아니다.

## 13. 최신 흐름과 발표자의 경험을 과장 없이 회수

트렌드는 새 용어를 더 외우는 장으로 만들지 않는다. 이번 강의에서 이미 보여준 흐름 세 가지로 정리한다.

1. 질문에 답하는 것에서 파일·코드·문서 같은 결과물을 만드는 흐름.
2. 모델 하나만 고르는 것에서 실행 환경·도구 연결·작업 지침을 함께 설계하는 흐름.
3. 자율 실행만 강조하는 것에서 진행 상황·승인·검증을 사람이 이어받는 흐름.

이를 업계 전체의 정량적 추세나 점유율이라고 표현하지 않는다. 공식 제품 문서에서 확인한 지원 방식의 변화로 한정한다. 예를 들어 데스크톱 작업 모드, Claude의 2026-09-16 제품 통합 안내, Remote 기능은 각각 날짜와 출처를 붙여 설명할 수 있다. [S22][S23][S25][S29]

기존 기획의 실제 프로젝트 경험은 보조 예시로 유지할 수 있으나 본편 시간을 더 쓰며 자동 확장하지 않는다. 프로젝트명·완료 여부·성능 수치·화면·저장소를 쓸 때는 제공된 원본과 공개 가능 범위를 확인한다. 'AI가 모두 알아서 했다', '시간을 몇 배 줄였다' 같은 근거 없는 성공담을 만들지 않는다.

마지막 회수 문장: **“내 목적에 맞게 고르고, 범위를 정해 맡기고, 실제 결과를 확인하고, 내 판단과 함께 기록하자.”**

수업 후 자율 시도 예시는 관심 있는 무료 경로 하나 확인하기, 자기 프로젝트의 목표와 검수 기준 적어보기 정도다. 제출·출석·채점·의무 결제는 없다.

## 14. 시각자료와 디자인 지시

공통 `PRESENTATION_AGENT.md`를 따른다. 흰색·흑백 미니멀, 16:9, 1920×1080 논리 캔버스, Pretendard, 제목 64px·본문 40px 등의 기존 토큰을 유지한다. 제목·본문·표·도식·주석·목차는 한국어로 실제 재작성하고, 한국어 줄바꿈·표 높이·그림 크기를 렌더링 결과에서 확인한다.

필수 시각자료는 회사/모델/앱/요금제 관계표, 용도별 추천표, CSU AI 연결도, 영상 카드, Agent 실행 루프, 하네스/Skill/MCP 역할도, 로컬 원격 연결도, 프롬프트 전후 비교, GitHub 작업 흐름이다.

실제 앱 화면이 없으면 설명용 도식으로 대체하고 '실제 UI'라고 적지 않는다. 화면을 확보하면 계정 정보는 가리고, 원본 비율을 유지하며, 학생이 읽어야 하는 메뉴를 충분히 확대한다.

Chart.js는 필요하면 사용하되 이번 회차에 숫자 차트가 필수는 아니다. USD 월 구독료, KRW 학생 혜택, 학교 크레딧, API 토큰 단가를 하나의 막대 차트로 비교하지 않는다. '공부력 90점/코딩력 95점' 같은 레이더 차트는 금지한다. 검증 가능한 같은 단위의 데이터가 없으면 표·관계도를 사용한다.

## 15. 발표 원고 지시

각 장에는 한국어 실제 발표 문장, 먼저 가리킬 위치, 중요한 오해, 다음 장 연결 문장, 출처를 넣는다. 학습용 상세 해설은 실제 읽을 원고와 분리한다.

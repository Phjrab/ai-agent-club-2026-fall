# QA와 완료 판정

정착 경로: `docs/QA_AND_ACCEPTANCE.md`

## 1. 결과 상태를 구분한다

- `PASS`: 해당 검사를 실제 수행했고 기준을 충족함.
- `FAIL`: 실제 수행했고 기준을 충족하지 못함.
- `BLOCKED`: 환경·권한·도구 때문에 수행할 수 없었음.
- `NOT_RUN`: 아직 수행하지 않았음.

`SKIPPED`를 PASS에 합산하지 않는다. 일부 검사가 막혀도 안전한 작업을 계속할 수 있지만, 전체 완료/공개 가능 여부는 별도로 판단한다. 문서에 적힌 체크리스트가 있다는 사실은 실행 증거가 아니다.

최초 private 저장소에는 미완성 구현을 정직한 상태로 push할 수 있으나, 공개 게시와 완료 badge는 관련 필수 검사가 통과한 경우에만 허용한다.

## 2. 콘텐츠 검수

| ID | 검사 | 통과 기준 |
|---|---|---|
| C01 | 필수 내용 커버리지 | brief의 requirement ID가 실제 slide ID와 연결됨 |
| C02 | 장수 | 본편·부록을 구분하고 목표와 실제 차이를 설명 |
| C03 | 제목 흐름 | 제목만 모은 개요가 논리적으로 이어짐 |
| C04 | 원본 충실성 | 중요한 Figure·표·수식·Algorithm·사례 누락이 없거나 분리 사유 있음 |
| C05 | 출처 참조 | 모든 factual claim의 source ID가 실제 registry 항목과 연결 |
| C06 | 수치 | 원시 데이터·가공식·단위·조건·표시값이 일치 |
| C07 | 최신성 | 가격·기능의 확인일과 실제 발표 시점 차이를 보고 |
| C08 | 경험과 해석 | 사용자 경험·설명 예시·공식 주장·추정을 구분 |
| C09 | 발표 방식 | 의무 실습·과제·실시 실적·학생 피드백을 임의 추가하지 않음 |
| C10 | 언어·용어 | 회차 언어와 glossary 일관성 유지 |
| C11 | 시간 | 본편 목표 시간과 slide duration 합계가 일치; Q&A 별도 |
| C12 | 입력 최신성 | brief digest 변경 시 deck를 검토·재작성하기 전에는 실패 |

모든 슬라이드가 외부 인용이 필요한 것은 아니다. 표지·목차·순수 안내는 `sourcePolicy: not_applicable`과 이유를 명시할 수 있다. 사용자 경험은 `sourcePolicy: personal_experience`와 사용자가 제공한 근거 범위를 명시한다. 허위 출처를 넣어 출처 유무 검사를 통과시키지 않는다.

## 3. DOM·스타일·이미지 검수

기준 viewport는 1920×1080, 축소 검토는 1280×720, 포트폴리오 모바일은 390×844로 한다. 실제 툴바가 차지하는 높이를 제외한 stage scale을 검증한다. 슬라이드 내부 요소를 모바일 레이아웃으로 재배치하지 않는다.

모든 slide를 직접 활성화하고 준비 완료를 기다린다. `display:none` 요소의 0 크기로 겹침 검사를 통과시키지 않는다.

검사 항목:

- 의도하지 않은 수평/수직 overflow, text clipping, 콘텐츠와 footer 충돌이 없다.
- 실제 텍스트 bounding box 또는 range rect가 부모 안전 영역을 벗어나지 않는다.
- 중첩된 부모·자식 요소를 정상 overlap으로 구분하고, 독립 콘텐츠끼리의 충돌을 찾는다.
- 이미지가 로딩됐고 naturalWidth/naturalHeight가 0이 아니며 종횡비가 유지된다.
- 제목·본문·캡션·footer의 역할별 최소 글자 크기와 위치 토큰이 지켜진다.
- 원본 Figure의 축·범례·단위가 보이고, 파일만 존재하지만 내용이 지나치게 작지 않다.
- 텍스트 대비와 색 이외의 의미 전달이 확인된다.

자동 bounds 검사는 시각적 품질의 일부만 확인한다. 실제 스크린샷으로 너무 조밀함·과한 공백·불균형·작은 원본 라벨·캔버스 내부 잘림을 점검한다.

## 4. 폰트 검사

Pretendard의 필요한 weight를 명시적으로 로드한다. `document.fonts.ready`만으로 모든 지정 폰트가 성공했다고 단정하지 않는다. FontFace 상태, 필요한 텍스트의 font loading 결과, 실제 렌더링을 확인한다.

테스트 문장은 최소 `AI Agent 활용 — 한글, 영문 GPT, 숫자 2026, 요금 ₩/$, MCP·Skill`을 포함한다. 깨진 네모, 한글 fallback, Bold 누락, 코드 안의 한글 깨짐이 없어야 한다.

Chart.js·Mermaid에 지정한 폰트도 별도로 검사한다. 늦은 font 로딩으로 축·박스 폭이 달라질 수 있으므로 그 이후 다시 렌더링한 결과를 캡처한다.

## 5. Chart.js·수식·도식 검사

차트마다 canvas 크기, 실제 차트 데이터, 축/범례 텍스트, 단위, source ID, 설명과 데이터 표를 확인한다. 0×0 canvas, 빈 그래프, NaN, 누락값을 0으로 변환한 데이터는 실패다.

막대 축·시간 순서·로그축·가공값이 설명과 일치해야 한다. 캔버스 DOM 영역이 정상이어도 내부 라벨이 잘릴 수 있으므로 축과 범례를 실제 이미지로 확인한다.

수식은 KaTeX error node·원문 TeX 방치·기호 누락을 확인한다. Mermaid는 라벨 잘림·화살표 방향·보안 설정·SVG의 임의 외부 참조를 확인한다. 코드·프롬프트는 화면에서 읽히는 최소 크기와 줄 수를 확인한다.

## 6. 준비 완료와 결정성

QA는 임의의 `sleep(2)`가 아니라 `slideReady(id)` 또는 `prepareForExport()`를 기다린다. 폰트, 이미지 decode, 차트, Mermaid, KaTeX, 필요한 layout이 완료되어야 한다.

날짜·랜덤·애니메이션을 고정해 비교 가능한 결과를 만든다. 스크린샷 픽셀은 브라우저·OS·폰트 렌더러에 따라 달라질 수 있으므로 기준 환경을 기록하고 다른 환경의 차이를 곧바로 디자인 회귀라고 단정하지 않는다. [R08]

모든 slide의 PNG와 컨택트시트를 생성한다. 컨택트시트만 보아 작은 라벨이 충분히 읽힌다고 판단하지 말고 chart·table·code·math slide는 원본 크기도 확인한다.

## 7. 탐색과 오프라인 재생

첫/끝 slide, 방향키·PageUp/Down·Space·Home/End, 목차 클릭, hash 직접 접속·새로고침, fullscreen 실패 복구를 시험한다. 공개 페이지에서 private 발표자 보기로 넘어갈 수 없어야 한다.

초기 의존성을 설치한 뒤 외부 네트워크를 차단하고 로컬 HTTP만 허용한 상태로 폰트·차트·수식·도식·탐색이 작동하는지 시험한다. `npm ci` 자체가 오프라인 설치를 지원한다고 별도로 주장하지 않는다.

GitHub Pages project base path를 모사한 `/ai-agent-club-2026-fall/` 아래와 `/`에서 링크·asset·deep link가 작동하는지 확인한다. 실제 owner를 하드코딩하지 않는다.

## 8. 내보내기 검수

### PDF

페이지 수 = 내보낸 slide 수. 16:9 페이지 박스, 한 페이지 한 slide, 빈 페이지 없음. footer와 Figure 전체가 보이며 font·chart·diagram이 화면과 의미상 동일하다.

실제 PDF를 렌더링해 페이지별로 확인한다. HTML 스크린샷만 확인한 상태에서 PDF 검수를 완료했다고 기록하지 않는다. 문서 분석 도구가 있으면 텍스트·페이지 수 검사도 병행한다.

### PPTX

파일이 정상 ZIP/Open XML 구조이고 slide 수·이미지 수·wide 비율이 맞아야 한다. 사용한 PPTX 라이브러리의 실제 API를 확인해 notes를 넣는다. 지원하지 못했다면 노트 누락을 보고한다.

가능한 Office/LibreOffice 또는 적절한 렌더러로 열어 실제 표시를 확인한다. 렌더러가 없으면 구조 검사는 PASS가 될 수 있어도 시각 검사는 BLOCKED다. `visual` PPTX를 편집 가능한 text/chart라고 안내하지 않는다.

### DOCX

각 slide ID/번호/제목이 deck와 일치하고 원고·학습용 해설·출처가 구분된다. 실제 문서를 열거나 렌더링해 한글 글꼴·페이지 분리·표·썸네일·머리말의 잘림을 확인한다.

학습용 해설까지 더해서 발표 원고 시간을 계산하지 않는다. 빈 슬라이드 대본이나 서로 다른 슬라이드 원고를 복제한 흔적을 확인한다.

### 산출물 manifest

파일명, 형식, 크기, SHA-256, source commit, 콘텐츠 digest, 슬라이드/페이지 수, 검사 상태를 기록한다. 파일이 없으면 다운로드 링크를 만들지 않는다.

## 9. 공개·보안 검사

공개 build 전에 다음을 모두 확인한다.

- 승인 hash가 현재 콘텐츠와 일치한다.
- private 노트, `.private`, 원본 첨부자료, 학생 정보, 이메일·전화번호, API 키, `.env`, 인증 파일이 없다.
- 공개 artifact에 불필요한 source map·내부 경로·비공개 강의 JSON이 없다.
- assets manifest에서 재배포 불명·검토 대기인 자산이 제외됐다.
- 미승인 강의가 목록·검색 index·thumbnail·sitemap·PDF·HTML cache에 남지 않았다.
- `dist/public`만 deploy artifact로 사용하고, 저장소 전체 또는 `dist/private`를 업로드하지 않는다.
- 원고 공개가 false일 때 HTML script/JSON/숨겨진 DOM에도 원고가 없다.

정규식 검사만으로 모든 비밀정보·권리 문제를 발견했다고 보증하지 않는다. Git 추적 파일, 변경 diff, 공개 대상 이미지와 문서를 함께 살핀다. 첫 공개 전환에서는 **Git 전체 이력도 공개된다는 점을 고려해 이력 범위까지 점검**한다.

## 10. 최소 실패 fixture

다음 문제를 넣은 테스트가 실제로 실패해야 한다. fixture는 사이트·실제 강의 산출물에서 제외한다.

1. 중복 slide ID, 존재하지 않는 source ID, 요구 주제 누락.
2. brief 수정 후 오래된 inputDigest.
3. 길어서 footer와 겹치는 본문, 원본 축이 잘린 이미지.
4. 로딩 실패한 Pretendard와 0×0 chart, chart 데이터 NaN.
5. 합계가 틀린 발표 시간, 부록을 본편에 중복 집계.
6. 미승인 강의와 `PRIVATE_TEST_SENTINEL_DO_NOT_PUBLISH`가 공개 artifact로 들어간 경우.
7. 승인 후 본문·차트 데이터 변경, 이전 승인 hash 재사용.
8. repo base path 아래의 잘못된 asset URL.
9. 에셋 경로의 `../` 탈출·스크립트 삽입·사용자 입력을 shell 문자열에 직접 결합하는 경우.
10. 생성되지 않은 export 파일을 가리키는 다운로드 링크.

## 11. 최종 보고

`reports/<run-id>/qa.json`, 사람이 읽는 `qa-summary.md`, slide 이미지, export manifest, 필요 로그를 생성한다. 실패 로그에서 민감한 경로·토큰은 제거한다.

검사 보고에는 실행 명령, 종료 코드, 환경, 대상 콘텐츠 digest, 검사 시각, 증거 경로가 있어야 한다. 보고 파일을 만들어 놓는 코드만 작성하고 실제 검사를 실행하지 않았다면 NOT_RUN이다.

공개 HTML은 콘텐츠·시각·privacy·source 검수 통과가 필요하다. 공개할 PDF 역시 PDF 검수가 필요하다. private 대본 DOCX나 선택적 PPTX 시각 검수가 막혔다면 전체 완료라고 보고하지 않되, 공개 대상이 아닌 해당 형식 때문에 안전한 HTML 개발까지 멈출 필요는 없다.

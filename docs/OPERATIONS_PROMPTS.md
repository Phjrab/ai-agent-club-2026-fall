# 이후 운영용 프롬프트

정착 경로: `docs/OPERATIONS_PROMPTS.md`

아래 프롬프트는 최초 구축 후 사용한다. 아직 없는 명령을 있는 것처럼 실행 완료로 보고하지 않는다. 각 작업은 현재 세션에서 수행하며, 예약·백그라운드 자동 실행을 기본적으로 만들지 않는다.

## 1. 다음 회차 제작

새 회차에 `templates/LECTURE_BRIEF_TEMPLATE.md`를 복사한 뒤 내용을 적는다. 실제 슬라이드 작성은 다음 지시로 Codex가 수행한다.

```text
AGENTS.md와 docs/PRESENTATION_AGENT.md를 읽고,
lectures/2026-fall/02-prompt-and-workflow/brief.md를 기준으로 이번 강의 자료를 제작해줘.
기존 발표 엔진과 디자인을 재사용하고, 이 강의에 필요한 최신 공식 자료만 확인해줘.
brief.md → deck.json/출처/데이터 → 한국어 원고 → HTML/PDF/visual PPTX/DOCX → 실제 QA까지 수행해줘.
이전 강의의 사실·날짜·승인 상태는 건드리지 말고, 이번 강의는 draft로 유지해줘.
필수 내용 커버리지, 예상 발표 시간, 확인이 필요한 정보, 생성 파일과 QA 증거를 보고해줘.
현재 저장소가 private이면 안전한 변경만 lecture 브랜치에 commit·push하고 PR을 만들어줘. 공개와 merge는 하지 마.
현재 저장소가 public이면 이번 draft의 소스 공개 승인이 없는 상태로 branch/PR에도 올리지 말고 로컬 결과와 필요한 승인 범위를 보고해줘.
```

`02-prompt-and-workflow`는 예시 slug다. 실제로 만든 강의 경로를 사용한다. `npm run lecture:new`는 폴더·입력 틀만 만들며 자체적으로 강의 내용을 집필하지 않는다.

## 2. 기존 강의 내용 수정

```text
AGENTS.md와 현재 Git 상태를 확인하고 01-agent-ai-intro 강의에서 아래 요청만 반영해줘.

[수정할 slide ID 또는 문장]
[바꿀 내용과 이유]

화면 본문과 한국어 발표 원고, 관련 차트·출처를 함께 수정하고 요구사항 커버리지를 다시 검사해줘.
수정된 brief의 해시와 deck 입력 상태를 일치시키되, 해시만 바꿔 검사를 통과시키지 마.
강의 내용이 바뀌면 기존 공개 승인 해시를 무효화해줘.
수정 장과 같은 레이아웃 대표 장을 다시 렌더링하고, export를 재생성해 QA 결과와 diff를 보여줘.
기존 확정 release는 덮어쓰지 말고 새 revision으로 남겨줘.
```

## 5. 공개 전 점검만 수행

```text

현재 추적 파일과 전체 Git 이력, 강의 원고, source registry, 이미지, generated public artifact를 확인해줘.
토큰·학생 개인정보·private 노트·재배포 불명 자산·미승인 강의·실적 과장을 찾아줘.
GitHub 저장소가 public이 되면 소스에 들어 있는 발표 원고도 보일 수 있다는 점을 별도로 확인해줘.
PUBLICATION_READY / PUBLICATION_BLOCKED로 판단하고, 근거·필요 조치·사이트 공개 범위를 기록해줘.
문제 해결을 위해 기존 이력을 강제로 바꾸거나 파일을 삭제하지 마.
```

## 6. 실제 public 전환과 Pages 게시

아래 지시는 public 전환을 원할 때만 사용한다. 자료의 코드·원고·이력까지 공개되는 범위를 먼저 확인한다. 상세 원고를 계속 비공개로 유지해야 한다면 repo public 전환을 승인하는 이 프롬프트를 사용하지 않고 별도 공개 대상 구성을 요청한다.

```text
이 강의 프로젝트의 public 전환과 GitHub Pages 게시를 승인한다.
공개 대상은 검토를 마친 01-agent-ai-intro 강의와 포트폴리오 소개다.
공개 저장소에서 추적된 일반 발표 원고도 공개 범위에 포함하는 것을 승인한다.
.private의 개인 메모, 학생 정보, 비밀정보, 재배포 불명 자료, 다른 draft 강의는 공개 대상이 아니다.

docs/GITHUB_AND_PUBLICATION.md에 따라 Git 전체 이력과 공개 artifact를 먼저 검사해줘.
범위 밖인 민감 자료나 권리 문제가 있으면 공개 작업을 멈추고 필요한 조치만 보고해줘.
문제가 없으면 해당 강의의 현재 콘텐츠 해시에 승인을 기록하고 공개 검수·CI를 통과시켜줘.
그 다음 저장소 가시성을 public으로 전환하고 Pages를 구성·배포해 실제 URL과 asset 로딩을 확인해줘.
라이선스는 내가 별도로 선택하지 않았다면 기존 pending 상태를 유지하고 임의의 MIT/CC를 붙이지 마.
실제로 공개된 내용, 공개되지 않은 내용, repo URL, 사이트 URL, commit/release를 보고해줘.
```

이 프롬프트의 “다른 draft 강의는 공개 대상이 아니다”는 repo 이력에도 적용된다. 이미 추적된 비공개 draft가 있다면 사이트에서 숨기는 것만으로 해결되지 않으므로 public 전환을 차단하고 선택지를 보고한다.
